# DECISIONS

## [2026-08-01] 全英文 UI + 底部持仓汇总随 `t` 切换

**背景**
中文一眼可读，不符合摸鱼伪装；持仓数据分散在表格列里，缺少组合维度的总览。

**决策**
- 界面与 CLI 交互全部英文：表头、状态栏 `Cols:`、`pos add` 交互提示、`add/rm/list` 输出。
- 底部新增汇总行随 `t` 切换：mode≥1 显示 `Value/Cost`，≥2 追加 `HoldP/L`，≥3 追加 `TodayP/L`（均为英文标签）。
- 今日收益率分母用昨日市值（Σ 昨收×股数），昨收缺失退回总成本。

**理由**
- 英文非母语不能一眼读懂，强化「在工作」伪装；与 `b` 键老板模式同一设计哲学。
- 底部汇总给组合总盈亏，收益方向红绿着色。

**备选方案**
- 仅翻译交互提示、其余保留中文 — 否，伪装不彻底。
- 汇总固定全显 — 否，随模式渐进展示，避免模式 0 时信息过载。

## [2026-08-01] 持仓管理命令改为 `pos`，`add` 采用交互式多选录入

**背景**
原 `bosskey position add CODE SHARES COST` 需手工背参数，且持仓股数/成本常需对照实际账户。

**决策**
- 子命令 `position` 缩短为 `pos`。
- `pos add` 无位置参数，纯交互：列出 watchlist 代码（已有持仓标 `*`）→ 编号逗号多选 → 逐个提示录入股数（正整数）与成本价（正数），带输入校验。

**理由**
- 交互式免去记参数和输错风险；多选一次可批量录入。
- 复用 watchlist 作为「可用列表」，已有持仓标 `*` 可同时支持更新。

**备选方案**
- 保留 `position CODE SHARES COST` 位置参数 — 否，用户明确要求交互式。
- `pos add` 额外支持位置参数快速录入 — 否，保持单一交互入口更简单。

## [2026-08-01] 持仓数据显示采用「循环显示模式」而非独立列开关

**背景**
需要支持添加/切换显示持仓、成本、持仓收益（率）、今日收益（率）。列多（最多 15 列），TUI 单键操作空间有限。

**决策**
- TUI 内按 `t` 在 4 种显示模式间循环：基础行情 → +持仓/成本 → +持仓收益/持仓收益率 → +今日收益/今日收益率。
- 模式为内存态，不持久化（与老板模式一致）。

**理由**
- 单键即可完成「切换」，渐进式展开列，模式语义清晰（每按一次多看一组）。
- 独立列开关需要多个按键，难记忆、难发现。

**备选方案**
- 每列独立热键开关 — 否，按键过多，不符合极简 TUI 定位。
- 一个键整体开/关全部新列 — 否，粒度太粗，无法只看持仓收益。

## [2026-08-01] 持仓数据存储于 `~/.bosskey.toml` 的 `[holdings]`

**背景**
持仓需要持久化（股数、成本价），与监控列表同源存储最简。

**决策**
配置新增 `[holdings]`，格式 `code = { shares = 股数, cost = 成本价 }`；CLI 用 `bosskey position add/rm/list` 管理；`position add` 同时把代码加入 watchlist。

**理由**
- 单一配置文件，无新增依赖，符合现有 `add/rm/list` 命令风格。
- 加入 watchlist 保证持仓股票必然出现在行情表中。

**备选方案**
- 独立持仓数据库/SQLite — 否，杀鸡用牛刀，TOML 已够。
